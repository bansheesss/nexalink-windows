# NexaLink 1.2

ریموت دسکتاپ چندسکویی (ویندوز / لینوکس) با پایتون: شبکه‌ی محلی + اینترنت (از طریق ریلی)،
رمز دائمی و رمز یکبارمصرف، تنظیمات قفل‌دار، دفترچه‌ی آدرس با برچسب، نسخه‌ی پرتابل ویندوز.

## جدید در ۱.۲
- **اینترنت:** سرور ریلی (`python main.py relay`). هر دستگاه با اتصال *خروجی* به ریلی وصل می‌شود؛ نیازی به باز کردن پورت یا IP ثابت نیست.
  ترافیک دو دستگاه سرتاسری رمز است و ریلی فقط بایت‌های رمزشده را رد می‌کند.
- **شبکه‌ی محلی:** مثل قبل مستقیم (کشف خودکار با شناسه). اتصال با شناسه ابتدا LAN را امتحان می‌کند، بعد ریلی.
- **رمز دائمی** (دسترسی بدون حضور) و **رمز یکبارمصرف** (یک ورود، با انقضا). هر دو همزمان فعال‌اند.
- **تنظیمات قفل‌دار:** برچسب دستگاه، دسترسی‌ها (فقط تماشا، انتقال فایل، کلیپ‌بورد، تأیید اتصال)، شبکه/ریلی، دفترچه‌ی آدرس با برچسب و تگ.
- **ویندوز پرتابل:** بدون نصب و بدون Administrator؛ همه‌چیز کنار برنامه در پوشه‌ی `data`.

## اجرا
    pip install -r requirements.txt
    python main.py                      # پنجره‌ی یکپارچه
    python main.py host --cli --otp     # میزبان بدون پنجره + رمز یکبارمصرف
    python main.py relay --token SECRET # سرور ریلی (روی VPS)

## راه‌اندازی اینترنت (۳ مرحله)
1. روی یک VPS: `python main.py relay --port 7072 --token SECRET` (یا Docker/systemd از پوشه‌ی `deploy/`). پورت TCP 7072 را باز کنید.
   برای TLS: `--cert fullchain.pem --key privkey.pem`.
2. روی هر دو دستگاه: تنظیمات ← شبکه و اینترنت ← آدرس ریلی، پورت، توکن (و «آزمایش اتصال»).
3. روی میزبان «شروع اشتراک» را بزنید (وضعیت ریلی «آنلاین» می‌شود)؛ روی بیننده شناسه ۹ رقمی + رمز را وارد کنید.

## ویندوز پرتابل
`python build.py --portable` (یا workflow «Windows portable» در GitHub Actions) ← `dist/NexaLink-portable-win64.zip`.
زیپ را باز کنید و `NexaLink.exe` را اجرا کنید. فایل `portable.flag` حالت پرتابل را روشن می‌کند.
محدودیت بدون Administrator: پنجره‌های elevated، UAC و صفحه‌ی قفل قابل کنترل نیستند.

## تست
    python -m unittest discover -s tests -v   # ۲۵ تست: پروتکل، ریلی، OTP، دسترسی‌ها، قفل تنظیمات، دفترچه
    python tests/ui_smoke.py                  # منطق UI بدون PyQt6 (نه رندر)

## پروتکل ریلی
مستند در `core/relay_proto.py`. خلاصه: ثبت میزبان با شناسه + کلید Ed25519 (اولین ثبت مالک شناسه است)،
توکن اختیاری مشترک برای جلوگیری از استفاده‌ی غریبه‌ها، جفت‌کردن دو سوکت و سپس کپی بایت‌ها.
پروتکل NexaLink (هندشیک، AES‑GCM، فریم‌ها) **تغییر نکرده** است؛ golden vectorهای اپ NexaLink اندروید بدون تغییر پاس می‌شوند.

## محدودیت‌های شناخته‌شده
- فعلاً همه‌ی ترافیک اینترنت از ریلی عبور می‌کند (P2P/hole punching هنوز نیست)، پس پهنای باند و تأخیر ریلی مهم است.
- قفل تنظیمات یک قفل رابط کاربری است، نه رمزنگاری فایل: کسی که به فایل `config.json` دسترسی دارد می‌تواند آن را ببیند/عوض کند.
  رمز دائمی در `config.json` ذخیره می‌شود (میزبان برای احراز هویت به آن نیاز دارد).
- هندشیک رمز-محور پروتکل در برابر حدس آفلاین توسط کسی که ترافیک را ضبط کند مقاوم نیست (رمز تصادفی بلند بگذارید؛ PAKE در نقشه‌ی راه).
- اندروید فعلاً فقط Viewer است و هنوز از ریلی/دفترچه‌ی آدرس پشتیبانی نمی‌کند.
